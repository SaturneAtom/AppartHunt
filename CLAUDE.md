# AppartHunt — notes pour Claude

- Langue : **français**, ton direct. L'utilisateur donne des intentions, pas des listes de critères : traduis-les, pose au plus 2-3 questions à la fois.
- **`recherche.md` = « Mes contraintes et choix »** : la référence de toute recherche. `profil.json` en est la version machine, que tu tiens à jour quand le texte change. **`zone.json`** décrit la zone : communes (code postal pour Leboncoin, identifiant Bien'ici, cercle 1 ou 2, note), quartiers (motif, note, position sur la carte). Aucun lieu n'est écrit dans le code : tout passe par ce fichier (`tools/zone.js`, `agent/src/agent_locataire/zone.py`). Sans ces fichiers, les exemples de `examples/` s'appliquent (Bordeaux, fictif).
- Un passage de recherche suit le skill `/agent-locataire` (`.claude/skills/agent-locataire/SKILL.md`). Outils : `./al tool <outil> '<json>' --run <RUN>`.
- **Toutes les données sont dans la base** `agent/data/agent.db` du dossier de recherche (annonces, fiches, choix, candidatures datées, journal des critères, ordre de la liste). Un seul accès : `python3 tools/donnees.py` (et `tools/suivi.py` pour garder / écarter / candidatures). Pas de fichiers JSON de données. `recherche.md` et `profil.json` restent des fichiers : ce sont les réglages.
- **Un seul dossier** : le code ici (versionné, public), les données de la recherche dans **`ma-recherche/`** (ignoré par git et bloqué par le hook) : `recherche.md`, `profil.json`, `zone.json`, `criteres.md`, `annonces.md`, `dossier/`, la base `agent/data/agent.db`, `archives/` (sauvegardes quotidiennes de la base). Les outils, `./al` et l'appli l'utilisent par défaut (`APPARTHUNT_WORKSPACE` pour en pointer une autre).
- Notes perso de la recherche en cours : @ma-recherche/notes.md
- Ajouter des annonces à la liste : `python3 tools/ajout.py lot.json "titre" "résumé"` (les met dans la base, régénère `selection.html`, complète le journal `annonces.md`).
- **Veille** (appli, `app/veille.js`) : toutes les 30 min de 8 h à 23 h, Leboncoin (onglet invisible, une recherche par cercle de la zone) + Bien'ici (API `realEstateAds.json`, identifiants de `zone.json`). **On reste large** : toutes les nouvelles annonces vont dans la liste, rien n'est caché. Mots-clés (bail étudiant/mobilité, saisonnier, coloc, RDC, > budget, DPE G) = une alerte « à vérifier » (champ `alerte` de la fiche), pas une élimination ; seules les demandes de logement sont mises de côté (`pasUneOffre`). Au moins 3 pages par recherche, jusqu'à 10 tant qu'il y a du nouveau, budget +10 %. L'agent (chat « Veille ») lit les annonces sans alerte ; les fiches Bien'ici sont déjà remplies. Outil `notifier`. Interrupteur marche/arrêt en haut de la colonne de l'agent : arrêtée, aucun passage automatique, même après réouverture, et un passage en cours s'arrête sans rien ajouter. Réglages, annonces vues et dernier passage : `veille.json` dans le dossier de l'appli.
- **Déboguer l'appli sans la relancer** : elle ouvre un port de débogage local (127.0.0.1:9333) ; `uv run --project agent python tools/appli.py etat | capture <png> | js "<expr>" | journal [n]`. Journal permanent : `~/Library/Application Support/AppartHunt/appli.log` (veille, agent, erreurs de la fenêtre). `APPARTHUNT_USER_DATA` pour lancer une deuxième copie de l'appli avec ses propres réglages et connexions (tests).
- **Carte** : sur la liste (bouton Carte) et sur chaque fiche, Leaflet dans `app/vendor/leaflet`, fond Esri (CARTO demande maintenant une clé, OpenStreetMap refuse les pages locales). Position de la fiche si l'annonce en donne une, sinon centre du quartier ou de la commune (`zone.json`, via `tools/geo.js`) ; commune inconnue (« Autre ») : pas de point.
- **Activité** (`app/sessions.js`) : une ligne par session de l'agent et par jour, et par passage de veille ; on ouvre pour lire tout le log (chaque commande, son résultat entier, à la seconde), relu des fichiers de session de Claude Code et copié dans `ma-recherche/logs/sessions/`. Le texte du raisonnement n'y est pas conservé, seulement sa durée.
- **Conversation : chaque chat est une tâche** (`app/taches.js`, sans Electron). Bouton « Répondre » sur les lignes Agent de l'onglet Activité et sur le log d'une session : le champ de la colonne indique à qui on parle, ✕ ou Échap ramène à la conversation d'où on vient. En cours, le message est écrit sur stdin et lu à la prochaine étape ; finie, arrêtée, plantée ou coupée, elle reprend avec `--resume` (mêmes options, même dossier ; stdin est fermé au `result`, le processus ne reste pas allumé). L'état (session, attente, non lus, coût, résultat) est dans `chats.json`. Une seule tâche à la fois, les reprises passent par la même file. L'agent voit les autres tâches avec `taches` et leur écrit avec `transmettre_a_tache`. Tests : `node app/tests/taches.test.js` (vrais appels, haiku, base à part), `agent/.venv/bin/python app/tests/ecran.test.py` (vrai écran, fausses données).
- **Le chat est Claude Code, pas un exécutant** : il modifie l'appli quand on le lui demande, sans proposer ni demander confirmation. Les outils et commandes de développement passent sans demander (liste `ALLOWED` de `main.js`, dont `python3` et `node`, donc en pratique tout ce qu'un script peut faire) ; toute autre commande affiche une carte Oui / Toujours / Non dans la conversation (outil `autoriser`, « Toujours » gardé dans `autorisations.json` ; jamais pour `rm` ni une commande composée). Seul `git push` reste interdit. Le rappel de reprise n'est ajouté qu'après une coupure, un arrêt, un plantage ou 30 min de pause.
- **Ce que le code garantit** : pas de reprise sans session existante ; refus si une autre tâche en cours a déjà la même annonce (candidature ou favori vus dans ses commandes, ou URL citée dans une demande de candidature) ; deuxième `envoyee` refusée par `suivi.py` ; message non lu jamais perdu (accusé `--replay-user-messages`, sinon reprise, sinon texte rendu dans le champ). **Ce qui n'est qu'une consigne** : `app/consignes/reprise.md` (vérifier l'état réel, ne jamais refaire une action), transmettre seulement sur demande, le cœur Leboncoin pas recliqué : l'IA peut s'y tromper.
- **Données perso jamais versionnées** (voir `.gitignore`, hook `.githooks/pre-commit`) : annonces, critères, zone, page générée, base de l'agent, dossier locataire.
- Dossier locataire : l'agent ne lit jamais le contenu des pièces, seulement leurs noms et dates. Chaque envoi est validé par l'utilisateur.

## Notes sur les sites

- **Leboncoin** bloque Playwright (« Accès temporairement restreint ») : passer par le Chrome de l'utilisateur (Claude in Chrome), en cliquant comme une personne. Données de la page dans `__NEXT_DATA__`. Refuser les cookies.
- **SeLoger** : marche si l'utilisateur est connecté (accueil → Louer → suggestion). Cœur favori : ne cliquer que si `data-testid` finit par `addButton` (`deleteButton` = déjà en favori, cliquer le retire).
- **Bien'ici** : relire l'appel `realEstateAds.json` de la page.
- **Locservice** : vérifier « Loué » et « Réservé aux étudiants » sur chaque fiche.
- **PAP**, **ParuVendu**, **Figaro Immo** : peu d'annonces en bail classique, beaucoup de saisonnier ou d'étudiant.
- Pièges fréquents : Studapart (toujours étudiant ou mobilité), baux « Code civil » de quelques mois, annonces de personnes qui *cherchent* un logement.
